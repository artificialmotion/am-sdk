# Changelog

All notable changes to am-sdk. The project follows semantic versioning; 0.x releases carry no compatibility promise.

## Unit data update (2026-10-12, within 0.2.0)

### Spec-locked unit data
- Unit data for all six units (S-S, S-D, M, H-F, H-T, H-X) now carries the spec-locked values (simulated, pre-hardware): ratings, typical 48 / 36 V continuous and 2 s peak curves, zero-speed 2 s hold, mass, reflected inertia, ratio and backdrive. Main changes: M peak 76.5 Nm (hold 71.5 Nm), inertia 0.0279 kg m2, backdrive 1.47 Nm; H-X ratio 23.4, OD 140 mm, 2.65 kg, inertia 0.180 kg m2, 136.41 Nm continuous; H-F peak 115 Nm.
- Peak curves start at the zero-speed 2 s hold, so a stalled joint is limited to the hold value rather than the rotating peak.
- Regenerated: `c/src/am_unit_data.c`, actuator-model specs, ROS 2 xacro.
- Tests updated to the locked values. The S-S estimator study uses Kd 3.5 (was 4.0) to stay inside the impedance envelope of the lower S-S inertia.

## 0.2.0 (release candidate; tagged at the public release)

### Public release preparation
- The three-clause licence statement: Apache-2.0 covers code, unit data, specs and the object dictionary (NOTICE, README).
- The named competitor catalogue specs and their generator entries are removed. Three unnamed, illustrative example specs replace them (`example_qdd_9to1`, `example_planetary_36to1`, `example_harmonic_100to1`, round numbers, not any real product). The notebook default is an illustrative example.
- Public names for four diagnostic objects: 0x2600:10 "Extended active fault set", 0x2603:1 "Start-inhibit reasons", 0x2700:2 "Supervisor request epoch / rearm epoch", 0x2700:3 "Supervisor condition bitmap". Values and indices are unchanged. `am_fault_info.boot_block` is now `start_inhibit` (C and Python).
- 1.0 compatibility scope in `docs/API.md` 4.7 is accepted.
- Version strings are 0.2.0 (Python `0.2.0`, no `.dev0`).
- `SECURITY.md`, `RELEASE.md`; `CONTRIBUTING.md` states that outside pull requests are closed until 1.0.


### API readiness for the public repository
- Renamed for public use (breaking, allowed in 0.x): `am_identity.fw_cm7` / `fw_cm4` are now `fw_main` / `fw_motor` (0x2100:1 main core, 0x2100:2 motor-control core); `AM_SIO_VM_GD_PRESENT` is now `AM_SIO_GATE_SUPPLY_PRESENT` (0x2620:1 bit 2). Python `AmIdentity` and `am_sdk.AM_SIO_*` follow. Python gains the `AM_SW_*` statusword constants that C already had.
- `docs/API.md`: version 0.2.0; full status-code table; family and provisional fault-code tables; what the 1.0 compatibility promise covers and what it does not; Python versioning; deprecation in practice; current-mode errors (`AM_ERR_NOT_SUPPORTED` vs `AM_ERR_STATE`) as implemented; ESI publication with the evaluation units.
- Header and docstrings: every public Python API function has a docstring with units, errors and [RT]/[NRT]; quick-stop wording matches 0x605A/0x6087; trace functions say 0.x.
- SPDX licence identifiers in every hand-written Python file; `python/LICENSE` and `python/NOTICE` so the Python distribution carries the licence; package metadata (classifiers, project URLs); absolute links in the Python README.
- README: third-party licences of the optional extras, and a statement that every unit value is a simulated typical design value.
- ROS 2 package versions follow the SDK version (0.2.0).
- `tests/test_release_metadata.py`: checks that every version string agrees, that the C and Python status codes, bit constants and fault names agree, and that the Python licence files match the top-level ones.

Torque estimation and collision detection without an output torque sensor. Simulated, pre-hardware: no accuracy is claimed; targets are in `docs/ESTIMATION.md`, to be confirmed on hardware.

### Showcase
- Simulated clips (`docs/media/`, MP4 and GIF, regenerated by `tools/showcase/`) and the Colab notebook `notebooks/check_your_actuator.ipynb`.

### C library
- `am_est.h` / `src/am_est.c`: baseline current-model estimator (temperature-corrected Kt with saturation, Stribeck + viscous friction or a friction map, forward/reverse gear efficiency or a load x temperature grid, output bearing), quality flags, uncertainty bound and confidence, optional bounded dither, momentum-observer collision detector with threshold, stick scaling and hysteresis. Fixed-size structs, no allocation.
- `am_est_calibration`: calibration record am_est_cal_v1.
- Tests: `test_est`; `am_est_xcheck` runner for the C/Python estimator cross-check. `test_cpp` includes `am_est.h`.
- API version 0.2.0 (`am_api_version()`).

### Python package
- `am_sdk.estimation`: the same estimator and detector, `EstimatorCalibration` with a JSON schema, `UkfTorqueEstimator`, learned-residual hooks (`LinearFeatureResidual`, `adoption_check`), all standard library only.
- `am_sdk.estimation.pinn.PinnResidual`: optional physics-informed MLP residual (extra `[pinn]`, numpy).
- Simulator: optional `SimOptions.truth_plant` (`TruthPlant`) and per-cycle ground truth `SimJoint.truth` (`SimTruth`). The default plant is unchanged.
- `am_sdk.estimation.simharness`: runs the estimators against the simulator and logs truth, estimates and collision events.
- Example `05_torque_estimation_collision.py`; tests `test_estimation.py`, `test_cross_check_est.py`.

### Docs and CI
- `docs/ESTIMATION.md`: method, assumptions, limitations, targets.
- CI runs the estimator cross-check and example 05; the Python 3.12 job installs `[pinn]`.

### Actuator model
- `am_sdk.actuator_model`: an open, thermal-aware actuator model for any actuator.
  - Spec schema `am-actuator-spec/1`, with a JSON Schema file and a stdlib validator.
  - `spec_from_datasheet()` builds a spec from minimal data, with flagged default assumptions.
  - `ActuatorModel`: torque limit vs speed, temperature and peak budget; copper and speed-dependent losses; 1-node or 2-node thermal network; derate, trip, duty cycle and events.
  - `BatchActuatorModel`: numpy or torch.
  - MuJoCo bank and MJCF snippets.
  - Isaac Lab `IdealPDActuator` subclass (untested on Isaac Lab).
- Specs for the six AM units and five catalogue examples at published face values (removed again in 0.2.0, see above). `tools/gen_actuator_specs.py` regenerates them.
- `docs/ACTUATOR_MODEL.md`, examples `05` to `09`, `tests/test_actuator_model.py`.
- Optional extra `batch` (numpy).

### ROS 2 (`ros2/`, simulated)
- `am_ros2_control`: `ros2_control` SystemInterface plugin on the C library. State interfaces position, velocity, effort (estimated torque), temperature; command interfaces position, velocity, effort, stiffness, damping. The drive mode follows the claimed interfaces; the lifecycle maps to the CiA 402 state machine. Backend `sim:<unit>`; `ethercat`/`canfd` are placeholders until evaluation units ship.
- `am_description`: xacro macros for every unit with limits from the unit data (generated by `tools/gen_ros2_xacro.py`), and the `ros2_control` block.
- `am_ros2_demo`: one joint with forward_command_controller, joint_trajectory_controller and an impedance controller.
- `am_ros2_bridge`: Python-only rclpy node on the Python simulator.
- `docs/ROS2.md`; CI workflow `ros2.yml` (ROS-free tests; colcon in ros:humble and ros:jazzy, non-blocking for now).

## 0.1.0

First release.

### C library (`c/`)
- `am_api.h`: L1 codec (`am_codec_*`) and L2 session API (`am_*`), C99, compiles warning-free as C and C++.
- Reference implementation: codec for RxPDO 0x1600/0x1601, TxPDO 0x1A00/0x1A01 and the CAN-FD compact profile; session layer over a pluggable `am_transport_ops` or the built-in simulator.
- `am_sim.h`: simulator controls (load, external torque, STO, faults, ambient, bus voltage) and a byte-level simulator transport.
- CMake build, CTest unit tests, examples `impedance_sine` and `leg_two_joints`.

### Python package (`python/`, `am_sdk`)
- Control API with the same calls as C.
- Simulator backend, MuJoCo coupling (`[mujoco]`), EtherCAT transport on pysoem (`[ecat]`), CAN-FD transport on python-can (`[can]`), and a `Transport` interface for your own master.
- Unit data for S-S, S-D, M, H-F, H-T and H-X.
- Tests, including a cross-check that runs the same command scripts on the C and Python simulators.

### Docs
- `docs/API.md`: layers, PDO byte layouts, CAN-FD profile, session model, error and versioning rules.
- `docs/object_dictionary.csv`: the object dictionary.

### Not in 0.1.0
- 20 kHz trace buffer access (`am_trace_*` return `AM_ERR_NOT_SUPPORTED`).
- Firmware update and service tools. They come with the evaluation units.
